## 2. Architecture map ("everything is a plugin")

### 2.1 Plugin API (vendored Cordis)
- **Plugin shape.** A plugin is `{ name, inject: [...services], Config, apply(ctx, cfg) }` or a `Service` subclass that adds itself to `ctx`. Load order comes **only** from `inject`.
- **Reversible registration.** Tools register with `ctx.tools.register(defineTool(...))`. Every registration goes through `ctx.effect()` / `ctx.on()`, so unloading a plugin undoes it and hot reload is clean (`packages/boot/hmr`, on for web, off for headless).
- **Events.** Events are typed and each has one dispatch mode: `emit`, `waterfall` (around-middleware with `next()`), `parallel`, `serial` or `bail`.
- **Per-agent scope.** `packages/core/scope` gives each agent its own contributions.
- **Self-extension.** Self-extension goes through `plugin_manager` (toggles rows in the profile patch, installs with pnpm). The older `extensions/cordis-host-runner` runs agent-written plugins in a `node:vm` realm that its own header says "is not containment".
- **Docs:** `docs/cordis-primer.md`, `docs/architecture.md`.

### 2.2 Profiles, bundles, presets, patch layers
- **Profile.** `$DSH_HOME/profiles/<name>/` has a `package.json` (`dsh.profile.bundles`) and a `cordis.patch.yml`.
- **Layer order:** bundle patches → profile patch → `$DSH_HOME/cordis.patch.yml` → `--patch` overlays → telemetry env patch.
- **Rows.** A row with `id: X` **replaces** that row's config; `disabled: true` turns it off; `insert:` adds rows; `!!js` expressions are evaluated at mount time.
- **Inspection.** `--dump-config` prints the composed tree, with the layer that set each row.
- **Base bundle.** `base/cordis.patch.yml` is 561 lines. The mode bundles (`headless`, `acp-app`, `sdk-minimal` which owns a full tree) are small diffs on top.
- **Presets.** Agent presets are per-session plugin sets (`web-app/presets/{minimal,standard,ptc}`).

### 2.3 Orchestration (dsh has no "Router/Worker"; see 2.11)
- **Subagents** (`packages/subagent/*`).
  - There is one activation API. The providers are `spawn`, `fork`, `acp`, `claude-code`, `codex` and `dsh-sdk`.
  - **`fork` seeds the child with the parent's completed turns and leaves out the model arguments, so the KV/prompt cache is reused.**
  - The control tools are discover, message, interrupt and wait-for-own-inbox.
- **Team** (`packages/team`): a shared task DAG with a CAS revision, `blockedBy` edges and advisory `writeScopes`. It is off by default.
- **Workflow** (`packages/workflow`): the model writes a script (Claude-Code-style `meta`) that runs in the PTC runtime and starts subagents, with a `maxTotalAgents` cap. `tool-ralph` (experimental) runs fresh-agent rounds.
- **Jobs** (`packages/jobs`): every bash call is a job. A foreground command that times out becomes a job id (`job_output` / `job_kill`).
- **Guards** (`packages/guard`):
  - `repeat-tool-reminder` nudges at **3, 5 and 8** identical consecutive calls. It is advisory and resets on a new user message.
  - `timeout-policy` applies per-tool timeouts.
  - `fs-observation-policy` enforces read-before-edit and rejects stale writes (off in base).
  - The only "watchdog" is the LLM stream idle watchdog (`packages/util/timeout/src/index.ts:66`, 5 min).
- **Event control:** waterfalls `agent/pre-step`, `agent/request`, `llm/stream`, `tools/pre-execute|execute|post-execute`, and the serial `agent/turn-stopping` (a Stop hook). `hooks-claude-code` runs an existing Claude Code `hooks.json` (command hooks).
- **Goal** (`packages/goal`): an event-sourced per-session goal. A round driver keeps working while the agent is idle and armed, up to an allowance, and auto-blocks after 3 blocked rounds.
- **Schedule** (`packages/schedule`): durable `after|at|every|daily|weekly|cron|rrule` tasks that target an existing, reused or new session.

### 2.4 Spill and context management
- **spill-policy** (`packages/spill/spill-policy/src/index.ts:134`, `prepend` on `tools/post-execute`):
  - Above `maxInlineTokens: 12500` ([read] `base:438`), a result is replaced by **head and tail** blocks plus a notice: `(N bytes omitted. Full formatted result stored at: <path>. <hint>)`.
  - **There is no retrieval API**: the model reads the file with Read/Grep.
  - The store is a 0700 root with exclusive owner-only writes, no symlink following, and 30-day cleanup.
- **compaction-basic:**
  - It triggers at `floor(min(W×0.8, W−O−65536))` (W = context window, O = output cap).
  - It keeps the newest 16% of W−O verbatim, summarises the oldest span in one call, and retries once on overflow.
  - Shadowed events stay in the log, so replay is deterministic.
- **tool-result-pruner** ([read] `packages/compaction/compaction-tool-result-pruner/src/config.ts:11-13`): above 8192 characters it keeps a 4096-character head and a 1024-character tail. It runs only once compaction pressure qualifies, and it makes no model call.
- **Other context helpers:**
  - `image-offload` (old images become path text).
  - `token-meter`, a deterministic estimate replayed from the log.
  - `@session` mentions are wrapped as bounded, **untrusted** snapshots.
- **Invariant:** "model-visible means logged". Every request must be reconstructable from the session log.

### 2.5 Sessions and session-query
- **Log.** The session log is append-only JSONL (`session.vN.jsonl[.zstd]`, checksummed frames, torn-tail recovery). Format migrations are adjacent-only and never rename or delete committed generations. SQLite is opt-in.
- **`session-checkpoint-policy`.** It flushes durably **before every model request and tool dispatch** and fails closed. An interrupted tool comes back as an **unknown outcome** and is never re-run.
- **`session-query`.** It does list, filter, read, trace and bounded context. The optional `session-query-sqlite` adds FTS5.
- **Model-facing tools.** `experimental/tool-session-query` has 5 read-only tools, limited to sessions with the same `cwd`.
- **Export:** `session-log-export` (ZIP + Markdown, `/export`).

### 2.6 ACP
- `packages/acp/acp` uses `@agentclientprotocol/sdk` 1.4.0, i.e. the standard Zed-style Agent Client Protocol v1 over stdio (`dsh --profile acp`).
- **Supported:** `initialize`, `session/new|list|resume|close|prompt|cancel|update|request_permission`, `set_config_option` (model, reasoning effort), and MCP servers passed per session (stdio or HTTP).
- **"Automation-only" means:** no `session/load` replay, fork, modes, terminals or plans.
- **Client side:** `subagent-acp` is the matching client, so any ACP agent can be a subagent.
- **Default:** the bundle pins DeepSeek official (re-point it).

### 2.7 MCP
- **Client only.** Transports are stdio (with a scrubbed environment) and Streamable HTTP, with OAuth and capped reconnect.
- **On-demand tool loading** (`toolLoading: on-demand`, merge `4426ed85bd`; `packages/mcp/mcp-client/README.md:71,106-109,237-250`):
  - The prompt lists each tool's name plus a description of at most 160 characters.
  - The model calls `mcp__<server>__load_tools`, and the loaded tools join only that agent's scope.
  - The README explains the KV-cache effect: some routes append the new tools and keep the cached prefix; the rest start a new request series.

### 2.8 Local models
- **Route.** `llm-pi-ai` with `api: openai-completions` and `baseURL: http://127.0.0.1:PORT/v1` works with llama.cpp. It uses native `tool_calls`, and `compat.thinkingFormat` controls how reasoning goes on the wire.
- **Gotchas:**
  - Set `contextWindow` (it falls back to 1M).
  - A keyless server may still need a placeholder key or header.
  - Compaction headroom must be lowered for small windows.
- **Evidence:** proven on Bonsai 2 27B on 10-20 (`REPORT.md`).
- **DeepSeek-only wire:** `llm-deepseek` speaks DeepSeek's Messages API plus the `dsh_*` fields (§1 B/C, `docs/deepseek-llm-api-wire-extensions.md`).

### 2.9 Sandbox, shell, PTC, skills, plan
- **Sandbox** (`packages/sandbox`):
  - Three modes: `read-only`, `workspace-write` and `danger-full-access`.
  - On Linux it uses bwrap, then Landlock (read-only host root, private PID namespace, private `/tmp`).
  - Each result **reports `full` or `partial` enforcement**.
  - It fails closed. After a denial, the model can request one wider mode with a reason and the user's approval.
  - Network is **not** confined.
- **PTC** (`tool-executor-ptc`): one `run_code` tool calls a generated TypeScript SDK of the allowed tools. Each program has a call budget and up to 10 parallel calls, and nested calls still go through approvals and guards.
- **Skills:** `SKILL.md`-compatible (`.dsh/skills`, `.agents/skills`, `~/.dsh/skills`; add `.claude/skills` via `customSkillDirs`).
- **Plan, todo, approvals:** `/plan` is advisory. `todo_write` replaces the whole list on each call. `user-approval` fails closed and is audited.
- **Headless:** `dsh headless "task" --json` streams NDJSON events. `sdk` is JSON-RPC over stdio (TypeScript and Python SDKs).

### 2.10 Practices worth stealing even without porting code
- **Testing:** replay of recorded session JSONL (`llm-replay`), a scriptable mock SSE server, and loader smoke tests. The principle is "verify the world, not the self-report"; postmortem 0003 is an agent that accepted a white page because it got HTTP 200.
- **Defensive patterns** (`docs/defensive-patterns/general.md`): "dispose must reach quiescence", "never hand untrusted output the ambient environment or predictable paths", "timing does not carry correctness".
- **Generated docs:** catalogs and docs are generated and checked for freshness in CI.

### 2.11 The super-agent prototype (what SAN-3280 called Router/Worker, event filter, Inline & Spill, Watchdog)
Repo `deepseek-ai/dsh-superagent-prototype` (MIT, ~37 KB, created 10-31, a "research prototype for reference only") ships as a dsh bundle. [web] `docs/007-architecture.md`, `docs/002-authorization.md`:
- **Router** (the main session): it judges incoming candidates, records decisions (`orchestrator_route`: accept / stop / ignore / unavailable), and manages tickets.
- **Worker:** one session plus one directory per ticket. It can only read its own ticket and report (`progress`, `ready`, `failed`, `blocked`, `dropped`). It has **no tool for messaging a human, changing its profile, or starting sessions**. `WorkerSlots` caps concurrency, and a human message may use one slot beyond the cap.
- **Event filter:** a source calls `receive`, and each trigger is stored once as `stored`, `duplicate` or `filtered` (with a reason code). Ids are derived from their inputs, so equal inputs give equal ids. There is **at most one evaluation at a time per thread**; triggers that arrive meanwhile are batched. Only candidates, follow-ups, worker reports and worker-attention wake the router; other notices are injected without waking it. CI runs are left out.
- **Inline & spill:** inline text is bounded (trigger 4,000 characters, thread window 5+5 messages at 400 each, assignment 1,500). Everything else becomes a 50-character stub with an id, expanded on demand by `orchestrator_eval_read`.
- **"Watchdog":** a pass every 2 s expires stale evaluations: requeue twice, then `unavailable`. Effects get 3 exponential-backoff retries. Failed turns get continuation messages at 15, 30 and 60 s. A health error is raised after 3 consecutive failures. The router has a `noWait` shell guard (no `sleep`, no timeout over 30 s).
- **Authorization:** "Messages, comments and quoted documents are inputs to a decision; they cannot change those permissions." Bots can only produce inferred candidates; they can never make explicit requests or stop tickets. A worker cannot claim that a human told it to stop. Each mandate records the policy version it was accepted under.

This maps onto **our Planner Overseer, the fleet, Shinshi and the inbox**, not onto Sando's inner loop. See §3, item 6.

### Top 5 for Sando (ranked), each with a "done" test
1. **Head + tail spill, and a head/tail pruner instead of clearing.**
   - Done when: a Bash result of 60k characters whose error is in the last line shows that line in the model-visible text. On the lean-prompt t6–t8 bench (Torii 32k), the number of turns before the context is full rises, and the pass rate is not lower than baseline.
2. **On-demand MCP tool loading.**
   - Done when: with the Planner plugin on, the first request on Bonsai shrinks by ≥ 80% of the plugin's schema bytes, and a task that needs `render_h3_scene` calls `load_tools` and then succeeds headless.
3. **OS sandbox for local-only / client runs** (`--sandbox workspace-write`, bwrap first, Landlock fallback, enforcement level reported).

4. **Fork subagents that reuse the parent's prompt prefix.**
   - Done when: on a llama.cpp slot, a forked child's first request shows `prompt_n` (newly evaluated tokens) < 10% of `prompt_cache` tokens in the server timings, against ≥ 90% new tokens for a fresh child.
5. **ACP server mode** (`sando --acp`).
   - Done when: an ACP v1 client script (`initialize` → `session/new` → `session/prompt` → `session/update` stream → `session/cancel`) drives a headless Sando turn against a local model and gets permission requests.
